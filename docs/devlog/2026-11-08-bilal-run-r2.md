## Observed behaviour

- **`Single-call LLM`:**
  - The model answered 43 of 44 builds in every seed (`ranking_source` = `llm`): one call per build, latency 95.6–226.3 s, median about 181 s.
  - `PR-1656_build1` (211 candidates) timed out at 480 s twice, call and retry, in all three seeds. It got one `FallbackRecord` (reason `timeout`) and the DANTE fallback ranking (`ranking_source` = `dante_fallback`).
  - `llm_relevance.csv` has one row per candidate for the 43 answered builds (8,484 rows) and no fell-back rows. `reason` and `confidence` are empty, because the single-call answer only gives scores.
- **Seeds:** the single-call relevance scores are identical in seeds 1, 2 and 3 (`temperature: 0.0`), so the `Single-call LLM` metrics are the same in every seed. `Random` is also identical across seeds, because `random_select` is called with `dante.random_seed` (42) from the config, not with the run seed. Both methods therefore show no seed-to-seed variation.
- **Phase 1 check (`E2_stored_phase1_seed1`, 50 builds):**
  - %DTC, `DANTE-CCH-shipped` vs `DANTE-CCH (stored)`: median difference 0.000, equal on 136 of 150 build-budget pairs.
  - Full-ranking APFDc, `DANTE-CCH-shipped` vs `rq1_dante_cch_apfdc` in `data_eval/eval_builds.csv`: median difference +0.0000, within 0.02 on 39 of 50 builds.
  - The median criterion holds. Phase 1 reported 45 of 50 builds within 0.02; the reason for the difference was not found (tie-breaking, #58, is one possibility, not checked).

## What went wrong

1. **`Single-call LLM` timed out on every build in the first attempt.** The single-call provider used `llm.timeout_s: 60`, which is shorter than generating scores for about 200 candidates on a T4. All 132 rows per seed were DANTE fallbacks.
   - Fix (#62, merged in #64): a separate `single_call.timeout_s`.
   - Its value, 480 s, was set from a timing run on 10 **dev** builds (`results/DEV_single_call_timing/`, slowest call 225.8 s). The timings of the failed test run were not used.
2. **`DANTE-CCH (stored)` rows were missing** from the first `E2_stored_phase1_seed1` (300 rows instead of 450), because `make_components` never set the stored loader. Fixed in #62/#64.
3. **The interactive Kaggle session kept `/kaggle/working` from an earlier session.**
   - The Python environment cell failed because `.venv` already existed. It was rerun with `uv venv --clear`.
   - The old `results/E2_stored_phase1_seed1/` folder was deleted before the run, so that `--skip-existing` could not reuse old rows; `skipped_existing` is empty.

Because of the fixes, E1 and E2_stored use commit `e63cf0b` and not the R1 commit `45e4496`. Apart from result files, trace samples, a devlog and tests, the two commits differ only in the two fixes (`experiments/run_experiment.py` and the `single_call.timeout_s` key in `config.yaml` and `config_kaggle.yaml`), and the non-LLM rows are identical on both commits.
